# Audience

Judge the work from the seat of whoever uses it.
The relevant user may be an end user, an API caller, the next maintainer, or a person reading a report.

- Name the user and their intended outcome before choosing a tradeoff.
- Favor a useful result for that user when implementation convenience conflicts with it.
- Require each feature or option to serve that user's task; remove what cannot justify its place.
- Explain the change through what the user can do or understand afterward.

Audience chooses whose outcome governs the decision.
Legibility measures code-reader effort, and design allocates UI attention.

See: `legibility`, `design`, `candor`.
