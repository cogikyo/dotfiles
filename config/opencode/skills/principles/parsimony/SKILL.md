# Parsimony

Delete before you build; the smallest change for observed needs wins.
Unnecessary parts make every later change harder, so remove them before investing in an addition.

- Call out obsolete code, unnecessary dependencies, and vestigial architecture as debt; remove dead parts, redundant validation, and unused layers before polishing or building on them.
- Require observed use or an explicit contract before adding guards, parsers, or abstractions.

See: `representation`, `legibility`.
